# Будова GrapeOS

## Окремий UEFI desktop

Desktop 0.3: `firmware/photos.c` декодує PNG/JPEG/BMP через stb_image
із UEFI-алокатором (обмеження 48 МіБ сумарно, 4 МіБ вхідний файл,
4 мегапікселі зображення). GUI має кешоване градієнтне тло і три кеші
білінійно масштабованих зображень. Термінал зберігає 80×25 символів та
кольори кожної комірки, відображає рідний шрифт Terminus 6×12 без згладжування;
сьомий стовпець комірки утворює проміжок між літерами.
`console_draw` передає малювання Snake у цей буфер, а `gui_input`
пересилає клавіші активній грі. Рендерер перетворює клітинки Snake
на графічні сегменти; neofetch використовує той самий кольоровий буфер.

Годинник верхньої панелі читає UEFI GetTime не частіше разу на секунду.
Команда `date` показує цей самий час без перетворення часового поясу.
Теми `grape`, `mint`, `midnight` змінюють лише палітру GUI й кешоване тло;
палітра термінала зберігається. Ctrl+Y або клік Theme перемикають тему.
Її індекс зберігається атомарним файловим записом у `/GRAPE/.desktop-theme`;
цей службовий файл не потрапляє до списку редагованих документів.

`make desktop` збирає x86_64 PE-програму зі стартом GNU-EFI. Вона залишає
BootServices активними й використовує `firmware/runtime.c` для GOP,
ConIn/ConInEx, SimplePointer/AbsolutePointer та годинника TSC. Спільні
GUI, оболонка, налаштування й ігри компілюються з `GRAPE_FIRMWARE`.
640×480 canvas масштабується в GOP зі збереженням пропорцій; F8 керує
курсором із клавіатури незалежно від pointer protocols.

Вивід порівнює фінальні пікселі з попереднім кадром у кешованій RAM
ділянками 16×16 й копіює у GOP лише змінені ділянки, об’єднуючи сусідні.
Незмінний кадр не записує відеопам’ять. Ввід обробляється пакетами до
64 подій перед кадром; GUI та консоль обмежують частоту оновлень до
50 кадрів/с. COM1 вмикається лише після перевірки scratch register;
завислий UART вимикається, щоб діагностичні повідомлення не блокували GUI.

`firmware/files.c` відкриває SimpleFileSystem лише на DeviceHandle
завантаженої програми після перевірки USB device path. Документи — звичайні
FAT-файли в `GRAPE`, з кешем на 32 файли до 4095 байтів. Збереження спершу
пише й Flush-ить окремий `.~new`, перевіряє вміст, перейменовує попередній
файл у `.~bak`, потім підмінює основний файл. Наступне завантаження
відновлює залишені резервні файли, коли основний відсутній. Профіль має
два записи з поколінням і контрольною сумою; нотатка також є `note.txt`.
Цей режим є UEFI-програмою; опис нижче стосується автономного i386-ядра.

## Завантаження

1. BIOS читає перший сектор образу за адресою `0x7c00`. Завантажувач
   нормалізує `CS`, сегменти даних і стек та вмикає VGA text mode 3.
2. `boot/boot.S` читає другий етап GrapeLoad з LBA 1–8 за адресою `0x8000`.
   `boot/grapeload.S` показує фіолетове меню з одним пунктом GrapeOS і чекає
   Enter від BIOS-клавіатури або COM1. До вибору ядро не читається.
3. Після Enter другий етап читає ядро з LBA 9 за адресою `0x10000`.
   Геометрія: 18 секторів на доріжку, 2 головки. Кожне читання має три
   спроби; після помилки контролер диска скидається. Завантажувач вмикає
   A20, встановлює GDT із плоскими сегментами коду й даних,
   установлює `CR0.PE` та виконує far jump у protected mode. Сегмент коду —
   `0x08`, сегмент даних — `0x10`, початковий `ESP` — `0x90000`.
4. `boot/entry.S` обнуляє BSS і викликає `kernel_main()`.
5. Ядро ініціалізує VGA і COM1, установлює IDT, перепризначає PIC, налаштовує
   PS/2 і PIT, дозволяє IRQ0, IRQ1 та IRQ12 за наявності PS/2-миші, а потім вмикає переривання. Драйвер
   ATA читає профіль з окремого локального диска. Новий профіль відкриває
   чотири кроки майстра; збережений — логотип і оболонку. `kernel/bootlog.c`
   показує виконані кроки ініціалізації та статус сховища й профілю.
   Після завершення логи видно дві секунди; ввід у цей час відкидається,
   щоб Enter з меню не заповнював майстер. Потім відкривається система.
6. Основний цикл читає спільний ввід для майстра, оболонки й активної гри.
   Snake отримує також події таймера. За відсутності вводу CPU виконує
   `hlt`; переривання таймера або клавіатури його пробуджує.

USB-образ має інший перший етап, `boot/usb.S`: він перевіряє EDD через
INT 13h AH=41h та читає GrapeLoad через AH=42h. Другий етап, зібраний
з `USB_BOOT`, також використовує абсолютні LBA, без CHS. 16-байтові
Disk Address Packet вирівняні на 16 байтів; лічильник секторів відновлюється
перед кожною спробою. Цей ABI перевірено за
[реалізацією INT 13h SeaBIOS](https://github.com/coreboot/seabios/blob/master/src/disk.c).
Обидва варіанти передають magic і прапорець live-режиму у восьми байтах
за адресою `0x7000` (`include/bootinfo.h`). USB-варіант вимикає ATA-сховище.

## Пам’ять

| Адреса / діапазон | Використання |
| --- | --- |
| `0x00007000` — `0x00007007` | Magic і прапорець live USB |
| `0x00007c00` — `0x00007dff` | BIOS boot sector |
| `0x00008000` — `0x00008fff` | GrapeLoad: меню, читання ядра й GDT |
| Від `0x00010000` | Код, константи, дані та BSS ядра |
| `0x00080000` — `0x0008ffff` | Діапазон, зарезервований під стек |
| `0x00090000` | Початкова вершина стека |
| `0x000b8000` — `0x000b8f9f` | 80×25 VGA-комірок по 2 байти |

У BIOS-версії paging вимкнений: лінійні адреси збігаються з фізичними. Linker перевіряє,
що точка входу — `0x10000`, а код, дані та BSS закінчуються до області стека.
Збірка відхиляє файл ядра, більший за 192 КіБ. Кожен сектор читається
окремо; при переповненні BX завантажувач підвищує ES на 0x1000 і оновлює
сегмент EDD-пакета. Жодна передача не перетинає межу 64 КіБ BIOS DMA.

Образ має 512-байтовий boot-сектор, рівно 4096 байтів GrapeLoad, ядро та
нульове доповнення до 1,44 МіБ. Збирач перевіряє цей формат і замінює
готовий образ атомарно, зберігаючи попередній файл для вже відкритої VM.

USB-образ має 65536 секторів (32 МіБ). MBR у LBA 0, GrapeLoad у LBA 1–8,
ядро з LBA 9. Активний FAT16 LBA-розділ типу 0x0e починається в LBA 2048,
має дві FAT, 512 кореневих записів і кластери по два сектори.
Його VBR має копію EDD-завантажувача з коректним BPB. README займає
один кластер; завантажувальні дані лежать поза файловою системою.
Збирач не використовує mkfs, loop-пристрої чи root і додає SHA-256 образу.

## UEFI x64

`scripts/build_uefi.py` створює 64-МіБ GPT-образ із захисним MBR,
основною й резервною таблицями GPT, CRC32 та FAT32 EFI System Partition.
`BOOTX64.EFI`, зібраний через `grub-mkstandalone`, містить ядро, шрифт меню
та конфігурацію GrapeLoad. Прошивка знаходить його в `EFI/BOOT/BOOTX64.EFI`.
Розділ має дві FAT, FSInfo та резервні boot/FSInfo-сектори.

GRUB завершує UEFI boot services і запускає ядро через Multiboot2.
`boot/uefi_entry.S` зберігає magic/адресу інформації, установлює власну GDT,
стек на 32 КіБ, обнуляє BSS і передає framebuffer у `kernel/framebuffer.c`.
UEFI ELF розміщено від 1 МіБ, окремим linker script; BIOS ELF залишається
за попередніми адресами. IDT та декодер i8042 спільні. У BIOS працюють
PIT/IRQ0, клавіатура/IRQ1 та PS/2-миша/IRQ12. У UEFI PIC залишається
замаскованим, IF=0, а час читається через TSC. Клавіатура й миша опитуються
за статусом i8042. `platform_idle()` виконує PAUSE, тому немає очікування
HLT на переривання, які сучасна прошивка може не маршрутизувати до PIC.
Це усуває шлях зависання після `Starting GrapeOS` на FX517ZC.

`kernel/clock.c` визначає частоту TSC за CPUID.15, інакше калібрує її через
PIT channel 2, незалежний від IRQ0. Якщо це недоступно, використовується
приблизна частота CPUID.16 або 1 ГГц. Калібрування має обмеження спроб;
`clock` показує джерело. Опитування споживає CPU навіть у простої; APIC,
енергозбереження й повноцінний планувальник залишаються майбутньою роботою.

Приймається RGB/BGR framebuffer 24/32 bpp із кроком рядка від завантажувача.
Чотири PAE page directories відображають RAM до 4 ГіБ, а вікно від
`0xe0000000` на 128 МіБ відображає фізичну відеопам’ять, також вище 4 ГіБ.
Для framebuffer використовується write combining через PAT за підтримки CPU.
`console.c` зберігає сітку 80×25 у RAM і малює її в GOP замість `0xb8000`.
GUI конвертує той самий буфер із чотирьох площин у RGB та масштабує
цілим коефіцієнтом. Шрифт 8×16 — ASCII із Terminus Font 4.49.1, SIL OFL 1.1.
Вхід/вихід із GUI й panic не програмують VGA-порти в UEFI-режимі.

UEFI встановлює той самий live-прапорець, щоб ATA-драйвер не звертався
до внутрішніх дисків. NVRAM емулятора завжди копіюється в тимчасовий файл.
На фізичному ПК firmware variables GrapeOS не змінює.

## Переривання й ввід

ISR-обгортки нормалізують кадри винятків із кодом помилки та без нього,
зберігають регістри й сегменти, вирівнюють стек перед викликом C і повертаються
через `iret`. Винятки друкують номер, назву, `EIP`, `CS` і код помилки; для
page fault також виводиться `CR2`. Після цього CPU зупиняється.

PIC переназначає IRQ0–IRQ15 на вектори 32–47. IRQ0 збільшує 32-бітний
лічильник PIT. IRQ1 декодує scan code клавіатури й додає символ у кільцеву
чергу на 128 комірок, з яких 127 доступні. Заповнена черга відкидає новий
символ. ISR не виконує команди й не друкує звичайний ввід.

COM1 налаштований на 115200 baud, 8N1. Ввід опитується основним циклом;
вивід консолі дублюється на VGA й COM1. Serial-клієнт може передавати Enter
як CR, LF або CRLF; стрілки історії — як ANSI `ESC [ A` та `ESC [ B`.
PS/2-контролер переводить scan code set 2 клавіатури в set 1.

Оболонка зберігає рядок у масиві на 128 байтів із завершальним NUL. Якщо
рядок завеликий, вона читає решту до Enter та відхиляє команду, щоб уникнути
виконання обрізаного вводу. Команди та їхні аргументи розбираються в цьому
буфері; історія зберігає окремі копії.

## Навмисний kernel panic

Точна команда `del ram` у `kernel/shell.c` запускає імітацію втрати
оперативної пам’яті через `kernel/panic.c`; інтерфейс оголошено в
`include/panic.h`. Ядро вимикає переривання, виводить діагностичний лог panic
на VGA і COM1 та зупиняє CPU. До оболонки керування не повертається;
для продовження потрібен зовнішній reset VM або закриття й новий запуск QEMU.

Цей сценарій не видаляє налаштування, установлені застосунки чи локальний
диск `data/grapeos-data.img`. Наступне завантаження читає збережений профіль
звичайним шляхом через GrapeLoad і сховище ATA.

## Логотип і neofetch

`kernel/fetch.c` малює кольорову символьну інтерпретацію наданого грона.
Еліпси описують ягоди; контур, фіолетова середина та світлі бліки
відображаються символами ASCII з різними VGA-атрибутами. Оригінальне PNG
збережено в `assets/grape-logo.png`. Графічний режим і декодер PNG для цього
не потрібні.

Праворуч від логотипа показуються ядро, архітектура, CPU, час роботи,
оболонка, розмір ядра й параметри консолі. `kernel/system.c` перевіряє
доступність CPUID і читає brand string або vendor string. `neofetch`
зберігає та відновлює кольори оболонки.

## Графічний режим

`gui` відкриває VGA 640×480 із 16 індексованими кольорами. `kernel/gfx.c`
програмує VGA mode 12h через порти. Буфер кадру в BSS має чотири площини
по 38400 байтів; кожна копіюється в `0xa0000` із відповідною маскою sequencer.
Шрифт малюється без зменшення: всі 16 рядків оригінального 8×16 символу.
Перед переходом зберігаються текстові регістри, DAC і 8-КіБ шрифт із plane 2.
Для доступу до шрифту вимикається doubleword addressing CRTC 0x14.
Після виходу або panic відновлюються шрифт, регістри й палітра.
Значення графічного режиму перевірено за
[таблицями SeaBIOS](https://github.com/coreboot/seabios/blob/master/vgasrc/stdvgamodes.c).

`kernel/gui.c` тримає чотири вікна з порядком накладання й фокусом:
Notepad, Terminal, Files, Calculator. Усі працюють у головному циклі ядра.
Є панель програм, згортання, переміщення мишею та клавіатурні скорочення.
Перемальовування відбувається при змінах, максимум 20 разів на секунду.
Термінал зберігає сітку 66×17 між перемиканнями; ввід і історія належать
існуючій оболонці. COM1 отримує текст і позначки відкриття програм.
Калькулятор викликає ту саму арифметику, що команда `calc`, із перехопленням
результату в окремий буфер без зміни графічного термінала.

Блокнот має чернетку до 255 символів, позицію курсора, вставку, Delete,
Home/End, рух стрілками й прокручування. Ctrl+S зберігає `note.txt` через
`store_save`, інші файли через `ramfs_write`. Files показує нотатку та
RAM-файли, відкриває їх у блокноті й дозволяє видалити RAM-файли.
`kernel/ramfs.c` містить 8 статичних слотів із назвою до 23 символів та
текстом до 255 байтів. Вбудовані системні імена захищені; rename працює
навіть коли всі слоти зайняті. Перезапуск обнуляє це сховище.

PS/2-миша ініціалізується bounded-командами F6/F4 через i8042 AUX.
Статус AUX відділяє мишачі байти від клавіатури. Трибайтові пакети
декодують знак, кнопки та рух із обмеженням координат 640×480.
Основний цикл отримує атомарний знімок; IRQ лише оновлює стан.
Драйверів USB HID та ASUS I2C-тачпада поки немає.

## Профіль і локальний диск

`run.sh` підключає два образи: завантажувальну дискету `build/grapeos.img`
і окремий primary master IDE `data/grapeos-data.img` на 1 МіБ. Диск даних
створюється виключно через відкриття нового файлу з `xb`; наявний файл не
перезаписується. `make clean` видаляє лише `build`.

`run.sh --usb` підключає `build/grapeos-usb.img` як USB mass storage,
лише для читання, без диска даних. Прапорець live-режиму забороняє
`store_init` навіть опитувати ATA; збереження застосовується лише до RAM.

`kernel/store.c` працює через ATA PIO на портах `0x1f0`–`0x1f7` та `0x3f6`.
Команди: IDENTIFY, READ SECTORS, WRITE SECTORS, FLUSH CACHE. Переривання ATA
вимкнено; готовність опитується з кінцевим обмеженням очікування. Для запису
підтримується окремий диск очікуваного розміру 2048 секторів.

Перші два сектори містять почергові версії профілю. Кожен запис має magic
`GRAPEST1`, версію формату, номер покоління, FNV-1a checksum і явно
серіалізовані поля: прапорець завершеного налаштування, ім’я користувача й
комп’ютера, кольори, бітову маску програм, нотатку та рекорд Snake. Під час
завантаження вибирається найновіший коректний запис. Новий запис вважається
збереженим лише після WRITE, FLUSH і перевірки повторним читанням. Помилка
запису залишає попередній стан RAM; без диска можливий режим на поточну сесію.

Майстер зберігає власну копію профілю й передає її сховищу лише на четвертому
кроці після підтвердження. Перше налаштування керується збереженим прапорцем,
тому повторний запуск VM не показує майстер знову.

## Застосунки й ігри

Каталог із Snake, Guess і Notes компілюється в ядро. `Grapemarket -I <name>`
встановлює біт доступності, `-R` прибирає його; дані програми залишаються
в профілі. Встановлені програми запускаються в просторі ядра. Тут немає
завантаження пакетів, мережі, ELF-завантажувача застосунків або ізоляції
процесів.

`kernel/input.c` переводить serial CR/LF/CRLF у один Enter, ANSI-стрілки
у спільні KEY_* та відрізняє окремий Escape від початку ANSI-послідовності.
Основний цикл спрямовує подію в активний майстер, гру або оболонку. Після
закриття модального застосунку відновлюється prompt.

Snake має масив до 640 комірок тіла, поле 40×16, пошук вільної комірки для
їжі з кінцевою кількістю спроб та крок кожні 20 ticks годинника. Він забороняє
негайний розворот, враховує рух хвоста й завершує раунд при зіткненні або
заповненні поля. Пауза зупиняє кроки. Рекорд записується при завершенні,
перезапуску або закритті раунду. Поле малюється безпосередньо в VGA через
`console_draw`, події гри передаються на COM1 через `console_serial_write`.

Guess обробляє введення числа без блокування головного циклу. Notes має
команди читання, збереження та очищення однієї нотатки. Віртуальні `ls` і
`cat` надають вбудовані тексти та поточні дані профілю, без повної файлової
системи.
