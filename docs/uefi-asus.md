# Оновлений desktop із постійними USB-файлами

Desktop 0.3 додає Photos (**Ctrl+P**), Snake (**Ctrl+G**) та neofetch
(**Ctrl+E**) у графічному терміналі. PNG/JPEG/BMP копіюються у папку
`GRAPE` на флешці, у Photos клавіша R оновлює список. Твоя картинка
`images.png` міститься на USB та вбудована у EFI як зразок.

Для курсора й справжніх документів використовується новий
`build/BOOTX64-desktop.EFI` замість попереднього GRUB-файлу.
Скопіювати його під іменем `EFI/BOOT/BOOTX64.EFI` на FAT-флешці.
GrapeLoad чекає Enter, показує логи, відкриває налаштування на першому
запуску, потім графічний стіл. Secure Boot має залишатися вимкненим.

F8 — курсор клавіатурою (стрілки + Enter/Space). Ctrl+F — Files,
Ctrl+A — новий файл, Ctrl+R — перейменувати, Enter — відкрити,
Ctrl+S — записати в блокноті. Документи й профіль містяться у папці
`GRAPE` на цій самій флешці. Внутрішній SSD не відкривається для запису.
Підтримка фізичної миші/тачпада залежить від UEFI pointer protocols.
Цей режим зберігає служби прошивки активними; він є UEFI-програмою,
а не автономним ядром із власними USB/NVMe-драйверами.

Далі — опис попереднього режиму i386/GRUB.

# GrapeOS UEFI для ASUS TUF Dash F15 2022

## Потрібний файл

**`build/grapeos-uefi.img`**, 64 МіБ: GPT, FAT32 EFI System Partition,
стандартний шлях `EFI/BOOT/BOOTX64.EFI`. Для FX517ZC потрібна ця версія.
Попередній `grapeos-usb.img` призначений для BIOS/Legacy.

За інформацією поточної Linux-системи ноутбук — ASUS TUF Dash F15
FX517ZC_FX517ZC, вбудована клавіатура — AT Translated Set 2 на i8042.
Використовуй **вбудовану клавіатуру**. USB-клавіатури після переходу в ядро
та тачпад поки не підтримуються власними драйверами.

UEFI-завантажувач використовує GNU GRUB, який завершує boot services і
передає керування ядру GrapeOS у protected mode. Картинка виводиться через
framebuffer, переданий GOP, з RGB/BGR та PAE для адрес вище 4 ГіБ.
Встановлення Linux або зміна внутрішнього диска не потрібні.

## Виправлення зависання на Starting GrapeOS

Попередній варіант після цього напису виконував HLT та чекав IRQ0 від
старого PIT. Якщо UEFI ноутбука не маршрутизує IRQ0/IRQ1 до PIC, запуск
зупинявся. Оновлений UEFI-варіант використовує CPU TSC, опитує вбудовану
клавіатуру та не залежить від цих переривань. Логи показують
`no legacy IRQ dependency`, джерело годинника й
`[BOOT] Opening welcome setup / desktop...`.

**Онови флешку:** перезапиши новий `build/grapeos-uefi.img` або заміни
`EFI/BOOT/BOOTX64.EFI` новим `build/BOOTX64.EFI`. Перезбірка на комп’ютері
не оновлює файл на флешці автоматично. Після запуску команда `clock`
показує джерело TSC, частоту та режим опитування.

Тести проходять у QEMU/OVMF з IF=0, тобто час і ввід працюють без IRQ.
Повторний фізичний запуск на ASUS ще потрібен для підтвердження.

## Збірка та перевірка на цьому комп’ютері

```sh
cd "/home/xiaomi2009user/Документи/grapeos"
make uefi
./run.sh --uefi
```

OVMF і QEMU вже є в локальній `.runtime`. На іншій машині потрібні GCC,
Binutils, Make, Python 3, GRUB із `x86_64-efi`, а для емулятора ще QEMU/OVMF.
Перевірки:

```sh
./run.sh --uefi --test
cd build
sha256sum -c grapeos-uefi.img.sha256
```

## Флешка

Візьми окрему флешку без потрібних файлів: запис образу **стирає її дані**.
Потрібно записати образ на весь USB-пристрій, а не скопіювати `.img` як файл.

1. Визнач флешку за моделлю, розміром та `TRAN=usb`:

   ```sh
   lsblk -o NAME,SIZE,MODEL,TRAN,MOUNTPOINTS
   ```

2. Відмонтуй її розділи у файловому менеджері. У команді нижче заміни
   `/dev/sdX` на пристрій **саме флешки**, наприклад `/dev/sdb`.
   Не вибирай внутрішній NVMe/SSD і не використовуй `/dev/sdb1`:

   ```sh
   sudo dd if="/home/xiaomi2009user/Документи/grapeos/build/grapeos-uefi.img" of=/dev/sdX bs=4M status=progress conv=fsync
   ```

3. Дочекайся завершення запису та безпечно витягни флешку.

Альтернатива для вже готової FAT32-флешки: створи на ній `EFI/BOOT` і
скопіюй туди `build/BOOTX64.EFI` з такою самою назвою. На UEFI x64 цей
стандартний шлях дозволяє запуск без запису нового образу. Сама флешка
повинна мати FAT32-розділ, який прошивка бачить.

## Налаштування ASUS

Цей завантажувач **не підписаний для Secure Boot**. Якщо Secure Boot
увімкнений, тимчасово вимкни його для запуску GrapeOS:

1. Повністю вимкни ноутбук. Затисни **F2** і натисни кнопку живлення,
   щоб увійти в налаштування UEFI.
2. **F7 → Advanced Mode → Security → Secure Boot → Secure Boot Control → Disabled**.
3. **F10** — зберегти налаштування. Ключі Secure Boot видаляти не потрібно.

Назви пунктів можуть трохи відрізнятися залежно від версії прошивки.
Якщо флешка не показується, ASUS також радить вимкнути `Boot → Fast Boot`.
Ці дії описані в офіційних інструкціях
[Secure Boot](https://www.asus.com/ca-en/support/faq/1050047/) та
[USB boot](https://www.asus.com/us/support/faq/1013017/).
Якщо використовуєш Windows із BitLocker, зміна Secure Boot може запросити
ключ відновлення; це також зазначено в інструкції ASUS.

## Запуск

1. Підключи флешку. На повністю вимкненому ноутбуці затисни **Esc**,
   натисни кнопку живлення й відпусти Esc після появи boot menu.
2. Вибери **UEFI: назва флешки**. Legacy/CSM вмикати не потрібно.
3. У меню **GrapeLoad / GrapeOS (UEFI)** натисни Enter.
4. Дочекайся логів і пройди майстер. Enter залишає значення за замовчуванням.
5. Введи **`gui`**. Ctrl+N — блокнот, Ctrl+T — термінал, Ctrl+S — зберегти
   файл; Ctrl+F — файли, Ctrl+K — калькулятор, Ctrl+B — згорнути вікно.
   Escape — повернутися до столу, ще Escape — в оболонку.

Esc і вибір USB для ноутбуків наведені в
[офіційній інструкції ASUS](https://www.asus.com/us/support/faq/1013017/).
Команди `help`, `neofetch`, `Grapemarket -I snake`, `snake` доступні в оболонці.

## Межі цієї версії

Перевірено завантаження в QEMU/OVMF, роботу GOP, PS/2, таймера, GUI,
блокнота, термінала, файлів, калькулятора, PS/2-миші, Snake, перезапуску й panic. Окремий тест перенаправляє
framebuffer у RAM вище 4 ГіБ та перевіряє реально записані пікселі через PAE.
На фізичному ноутбуці попередній образ уже дійшов до логів ядра;
виправлення зависання треба підтвердити повторним запуском нового образу.

Система працює в live-режимі. Профіль, нотатки, програми й рекорд існують
до перезапуску. Драйвер ATA вимкнений; внутрішні диски не читаються й не
записуються. Після тестування можна витягнути флешку та завантажити
попередню ОС звичайним способом.

Режим опитування тримає CPU зайнятим у простої, тому це тестовий live-сеанс,
а не реалізація енергозбереження. RAM-файли також зникають після перезапуску.
